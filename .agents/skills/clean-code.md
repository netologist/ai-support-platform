# Clean Code Skill

## Use when

- Reviewing design quality, refactoring, or deciding whether a new abstraction is justified.

## Conventions

- Prefer clear names over explanatory comments.
- Remove duplication when it reflects the same policy, not just similar syntax.
- Keep modules cohesive and dependencies directional.
- Avoid speculative abstractions.
- Optimize first for correctness and clarity, then for local convenience.
